# FORGE

An open-source gameplay framework mod for Farming Simulator 25, written in Lua: a core engine plus ForgeOS, an in-game phone and laptop that apps (such as Communications) run on. Read by Claude Code and Codex.

## How we work
1. **The user decides.** You propose and build; design, scope and acceptance are the user's call. A plan, doc or half-built file is never permission to continue.
2. **Plan first, beyond small fixes.** A small fix touches one file and changes no design. Anything bigger: show what changes, which files, the risks and anything you're unsure of, then wait for a yes. If the work would contradict an approved doc or needs an undecided choice, say so instead of choosing.
3. **Design before code.** How a subsystem works is set in its `docs/` folder. Approved docs and ADRs are the contract; Draft and Review docs are not.
4. **One source of truth.** Edit only the real source; run `tools/sync.py` to update the prototype. Generated copies and packages never replace source.
5. **Prove it in the game.** A batch is done when the FS25 runtime check passes and the user accepts it. Evidence goes in `docs/reviews/evidence/`. Never rebuild an accepted package just for a new hash.
6. **Protect the repo.** Ask before deleting, moving or renaming. No commit or push without a yes. Leave unrelated changes alone.
7. **Report plainly.** After work: what changed, what you checked, what's unresolved, and the Git state. Keep facts, guesses and suggestions apart. Plain English; code detail only when asked.
